# CI/CD 파이프라인 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `main` 브랜치에 push(=PR 머지)되면 Docker 이미지를 빌드해 GHCR에 push하고, 가비아
서버에 SSH로 접속해 새 이미지를 pull & 재기동하는 CD 파이프라인을 구축한다.

**Architecture:** 기존 `ci.yml`(PR 검증용 lint/test/build)은 그대로 두고, `main` push를
트리거로 하는 신규 `cd.yml`을 추가한다. `cd.yml`은 (1) Docker 이미지 빌드 & GHCR push,
(2) 가비아 서버로 compose 파일 전송 + SSH 접속 후 `docker compose pull && up -d` 두 단계로
구성된다. 서버는 아직 발급 전이므로 `deploy` job은 시크릿이 채워지기 전까지 실패하는 게
정상이며, `build-and-push` job까지는 지금 바로 검증 가능해야 한다.

**Tech Stack:** Kotlin 2.3.21 / Spring Boot 4.1.0 / JDK 25(Gradle toolchain) / Gradle
9.5.1(wrapper) / Docker / GitHub Actions / GHCR / MongoDB 8

## Global Constraints

- 참조 스펙: `docs/superpowers/specs/2026-08-03-ci-cd-design.md`
- JDK 25 (Gradle toolchain, `build.gradle.kts`의 `java.toolchain`과 동일 버전 사용)
- Gradle wrapper 버전 9.5.1 (`gradle/wrapper/gradle-wrapper.properties`), 이미지 빌드 시
  반드시 `./gradlew` wrapper로 빌드 (별도 Gradle 설치 이미지 사용 금지)
- 이미지 레지스트리/이름: `ghcr.io/nexters/git-it-server` (태그: `{sha}`, `latest`)
- 운영 compose에서 MongoDB는 호스트에 포트 노출하지 않음 (내부 네트워크만 사용)
- GitHub Secrets는 정확히 4개만 사용: `GABIA_HOST`, `GABIA_USERNAME`, `GABIA_SSH_KEY`,
  `PROD_ENV_FILE` (환경변수별로 시크릿을 쪼개지 않는다)
- `cd.yml` 트리거: `push` to `main`만 (PR 이벤트 아님, 기존 `ci.yml`과 트리거 겹치지 않음)
- 범위 제외: 무중단 배포, 스테이징 환경, 리버스 프록시/HTTPS — 추가하지 않는다

---

## File Structure

- **Create** `Dockerfile` — 멀티스테이지 빌드 (Gradle wrapper 빌드 → JRE 실행 이미지)
- **Create** `docker-compose.prod.yml` — app + mongodb 운영 compose 정의
- **Create** `.github/workflows/cd.yml` — 이미지 빌드/push + SSH 배포 워크플로
- **Modify** `README.md` — 배포(CD) 섹션 추가

### Task 1: Dockerfile 작성 및 로컬 빌드/기동 검증

**Files:**
- Create: `Dockerfile`

**Interfaces:**
- Produces: `git-it-server:test` 로컬 이미지 태그 (이후 Task 2/3에서 참조하는 실제 운영
  이미지 이름은 `ghcr.io/nexters/git-it-server`이며 별개)

- [ ] **Step 1: `Dockerfile` 작성**

프로젝트 루트에 다음 내용으로 작성한다.

```dockerfile
# syntax=docker/dockerfile:1
FROM eclipse-temurin:25-jdk AS build
WORKDIR /workspace
COPY . .
RUN ./gradlew bootJar --no-daemon -x test

FROM eclipse-temurin:25-jre
WORKDIR /app
COPY --from=build /workspace/build/libs/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

`-x test`는 이미지 빌드 시 테스트를 건너뛴다는 뜻이다 (테스트는 이미 `ci.yml`에서
PR 단계에 실행되므로 이미지 빌드에서 중복 실행할 필요가 없다).

- [ ] **Step 2: 이미지 빌드**

Run: `docker build -t git-it-server:test .`

Expected: `[+] Building ... FINISHED`로 성공 종료 (non-zero exit이면 실패)

- [ ] **Step 3: 로컬 MongoDB 기동 확인**

Run: `docker compose -f docker-compose.local.yml up -d && docker compose -f docker-compose.local.yml ps`

Expected: `git-it-mongodb` 컨테이너 STATUS가 `healthy`

- [ ] **Step 4: 빌드한 이미지로 컨테이너 기동 스모크 테스트**

Run:
```bash
docker run --rm -d --name git-it-smoke \
  -p 8080:8080 \
  -e MONGODB_HOST=host.docker.internal \
  -e MONGODB_PORT=27017 \
  -e MONGODB_DATABASE=gitit \
  -e MONGODB_USERNAME=gitit \
  -e MONGODB_PASSWORD=gitit1234 \
  -e JWT_SECRET=docker-smoke-test-jwt-secret-1234567890 \
  -e OAUTH_GOOGLE_CLIENT_ID=smoke-test \
  -e OAUTH_APPLE_CLIENT_ID=smoke-test \
  git-it-server:test
sleep 8
curl -f http://localhost:8080/v3/api-docs
```

Expected: `curl`이 HTTP 200과 OpenAPI JSON을 반환 (실패 시 `docker logs git-it-smoke`로
원인 확인)

- [ ] **Step 5: 스모크 테스트 컨테이너 정리**

Run: `docker stop git-it-smoke`

- [ ] **Step 6: Commit**

```bash

git commit -m "feat: 운영 배포용 Dockerfile 추가"
```

### Task 2: `docker-compose.prod.yml` 작성

**Files:**
- Create: `docker-compose.prod.yml`

**Interfaces:**
- Consumes: Task 1에서 정한 컨테이너 포트 `8080`
- Produces: `app`, `mongodb` 서비스명 (Task 3의 배포 스크립트가 이 파일 경로를 참조)

- [ ] **Step 1: `docker-compose.prod.yml` 작성**

```yaml
services:
  app:
    image: ghcr.io/nexters/git-it-server:latest
    container_name: git-it-app
    restart: unless-stopped
    env_file: .env
    ports:
      - "8080:8080"
    depends_on:
      mongodb:
        condition: service_healthy

  mongodb:
    image: mongo:8
    container_name: git-it-mongodb
    restart: unless-stopped
    environment:
      MONGO_INITDB_ROOT_USERNAME: gitit
      MONGO_INITDB_ROOT_PASSWORD: gitit1234
      MONGO_INITDB_DATABASE: gitit
    volumes:
      - mongodb-data:/data/db
    healthcheck:
      test: ["CMD", "mongosh", "--quiet", "--eval", "db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 10s

volumes:
  mongodb-data:
```

`docker-compose.local.yml`과 달리 `mongodb`에는 `ports:`가 없다 — 호스트에 27017을
노출하지 않고 `app` 서비스와 같은 기본 네트워크로만 통신한다.

- [ ] **Step 2: 문법 검증**

`env_file: .env`를 읽으려면 `.env`가 있어야 하므로, README가 안내하는 로컬 셋업과
동일하게 준비한다 (이미 있다면 건너뜀).

Run:
```bash
test -f .env || cp .env.example .env
docker compose -f docker-compose.prod.yml config
```

Expected: 에러 없이 병합된 compose 설정이 출력됨 (services: app, mongodb 포함)

- [ ] **Step 3: Commit**

```bash
git add docker-compose.prod.yml
git commit -m "feat: 운영 배포용 docker-compose.prod.yml 추가"
```

### Task 3: `.github/workflows/cd.yml` 작성

**Files:**
- Create: `.github/workflows/cd.yml`

**Interfaces:**
- Consumes: Task 2의 `docker-compose.prod.yml` (서버로 복사되는 파일), Task 1의
  `Dockerfile`(빌드 컨텍스트)
- Consumes secrets (서버 준비 후 사용자가 등록): `GABIA_HOST`, `GABIA_USERNAME`,
  `GABIA_SSH_KEY`, `PROD_ENV_FILE`
- Produces: `ghcr.io/nexters/git-it-server:{sha}`, `ghcr.io/nexters/git-it-server:latest`
  이미지

- [ ] **Step 1: `.github/workflows/cd.yml` 작성**

```yaml
name: Backend CD

on:
  push:
    branches:
      - main

permissions:
  contents: read
  packages: write

jobs:
  build-and-push:
    runs-on: ubuntu-22.04
    steps:
      - name: action checkout
        uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push image
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/nexters/git-it-server:${{ github.sha }}
            ghcr.io/nexters/git-it-server:latest

  deploy:
    needs: build-and-push
    runs-on: ubuntu-22.04
    steps:
      - name: action checkout
        uses: actions/checkout@v4

      - name: Copy docker-compose.prod.yml to server
        uses: appleboy/scp-action@v0.1.7
        with:
          host: ${{ secrets.GABIA_HOST }}
          username: ${{ secrets.GABIA_USERNAME }}
          key: ${{ secrets.GABIA_SSH_KEY }}
          source: "docker-compose.prod.yml"
          target: "~/git-it"

      - name: Deploy over SSH
        uses: appleboy/ssh-action@v1.2.0
        with:
          host: ${{ secrets.GABIA_HOST }}
          username: ${{ secrets.GABIA_USERNAME }}
          key: ${{ secrets.GABIA_SSH_KEY }}
          script: |
            cd ~/git-it
            cat > .env <<'ENVEOF'
            ${{ secrets.PROD_ENV_FILE }}
            ENVEOF
            docker compose -f docker-compose.prod.yml pull
            docker compose -f docker-compose.prod.yml up -d --remove-orphans
            docker image prune -f
```

- [ ] **Step 2: YAML 문법 검증**

Run: `ruby -ryaml -e "YAML.load_file('.github/workflows/cd.yml'); puts 'valid'"`

Expected: `valid` 출력, 에러 없음

- [ ] **Step 3: Commit**

```bash
git add .github/workflows/cd.yml
git commit -m "feat: main push 시 GHCR push 및 가비아 서버 배포 워크플로 추가"
```

**Note:** `build-and-push` job은 지금 바로(이 브랜치가 main에 머지되는 시점) 동작을
확인할 수 있다. `deploy` job은 `GABIA_HOST`/`GABIA_USERNAME`/`GABIA_SSH_KEY`/
`PROD_ENV_FILE` 시크릿이 등록되기 전까지는 연결 실패로 끝나는 게 정상이며, 이는
스펙 문서의 테스트 계획에 명시된 예상 동작이다.

| `PROD_ENV_FILE` | 운영 `.env` 파일 전체 내용 |

[`docs/superpowers/specs/2026-08-03-ci-cd-design.md`](docs/superpowers/specs/2026-08-03-ci-cd-design.md)를
